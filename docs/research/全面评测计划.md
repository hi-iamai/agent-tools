# Agent 底层 Tool 全面评测计划

## 1. 目标修正

现有报告只完成了一个 Pilot：

- 单一代码仓；
- 主要使用 `ripgrep`；
- 对比 Shell、专用 Tool、最小 Router；
- 只覆盖本地只读代码检索。

该 Pilot 只能说明 Tool Surface 会显著影响 Agent 行为，不能回答底层 Tool
方案全貌。正式评测目标调整为：

> 不预设最终组合，尽可能验证已有可运行的 Tool 类型、Backend、运行形态和
> 结果处理方案，分别给出性能、正确性、资源、覆盖语义和失败模式数据。

## 2. 评测维度

每个方案至少分开测量：

1. Engine 原始性能；
2. Tool Adapter 后的性能；
3. 结果完整性与语义差异；
4. 冷启动、热启动和索引构建；
5. CPU、峰值内存、输出字节；
6. 并发 1/4/8；
7. 异常、超时、编码、二进制和大结果；
8. Agent 端到端抽样表现。

## 4. 环境

分别报告：

- Windows Native；
- Ubuntu 24.04 WSL；
- WSL 挂载 Windows 工作区；
- WSL Linux 根文件系统副本。

当前 WSL 是 WSL1，因此数据只能代表 Linux userspace + WSL1 文件系统/系统调用
特性，不能直接写成原生 Linux 内核结果。

## 5. 报告原则

- 不输出一个笼统总冠军；
- 不用综合分掩盖语义差异；
- 每类 Tool 给出 Pareto 前沿；
- 区分“快但覆盖范围窄”和“慢但语义更强”；
- 未运行的候选单独列出原因；
- Pilot 结果与正式结果分开；
- 公开原始 JSONL、版本、命令和判题器。
